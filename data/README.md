# Dataset Collection and Justification

## Purpose

The project needs data that separates additive noise from room reverberation and also supports a fair real-time evaluation. The collection plan therefore uses one supervised denoising benchmark, one broad noise-suppression source, one reverberation benchmark, and controlled mixtures with known clean references.

## Recommended sources

| Source | Role | Justification | Collection decision |
|---|---|---|---|
| [VoiceBank-DEMAND / Edinburgh DataShare](https://datashare.ed.ac.uk/handle/10283/2791) | Parallel clean/noisy speech | Provides paired speech examples for supervised denoising and objective before/after comparison. | Start with the test set and a documented speaker-disjoint subset; preserve the source licence and citation. |
| [DNS Challenge data and scripts](https://github.com/microsoft/DNS-Challenge) | Noise, clean speech, room impulse responses, and challenge-style mixtures | Provides real-world noise diversity and includes a synthesis workflow for noisy and reverberant speech. | Use a manageable development subset first; the full DNS5 download is very large and should not be copied without storage approval. |
| [REVERB Challenge](https://reverb2014.audiolabs-erlangen.de/index.html) | Reverberant speech and dereverberation evaluation | Directly represents distant-talking speech in real and simulated rooms and includes dereverberation/ASR evaluation procedures. | Request the dataset through its current LDC access route when a formal dereverberation benchmark is required. |
| Controlled mixtures generated by this project | Development and ablation data | Clean speech, noise level, room impulse response, and RT60 are known exactly, which makes debugging and controlled comparisons possible. | Use the built-in generator for smoke tests and ablations; do not present it as a substitute for human-speech benchmarking. |

## Directory convention

```text
data/
  raw/
    voicebank_demand/
    dns/
    reverb/
  processed/
    train/
    validation/
    test/
  manifests/
```

Keep raw source data outside Git. Store only manifests, configuration, checksums, and small reproducible fixtures in the repository. Do not redistribute a dataset if its licence or access agreement does not permit redistribution.

## Collection procedure

1. Record the source URL, access date, licence, citation, version, and local storage path.
2. Keep speakers disjoint between train, validation, and test wherever the source supports that split.
3. Normalize metadata without altering the raw audio. Record sample rate, channels, sample width, duration, and file count.
4. Convert or resample only into a separate processed directory, preserving the original files.
5. Generate a JSON manifest for every split:

```powershell
python -m realtime_speech_enhancement.dataset data/raw/voicebank_demand/test `
  --dataset-name voicebank_demand `
  --split test `
  --output data/manifests/voicebank_demand_test.json
```

6. Use the controlled generator to create additional noisy/reverberant pairs with recorded SNR and RT60 settings.
7. Store the manifest alongside every evaluation report so results remain traceable to the exact files used.

## Why this combination is sufficient for the current milestone

VoiceBank-DEMAND gives a clear paired denoising baseline, DNS provides robustness to varied noise and room conditions, REVERB isolates the dereverberation requirement, and controlled mixtures make causal algorithm debugging repeatable. Together they cover the project's two distortions, supervised evaluation, real-world variability, and reproducibility constraints without pretending that one dataset represents every deployment environment.
